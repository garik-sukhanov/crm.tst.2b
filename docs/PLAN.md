### 3. База данных и безопасность (Supabase)
- [ ] схема: `profiles` (роль), `objects`, `tasks`, `task_status_history`, enum статусов
- [ ] RLS для всех таблиц: постановщик видит всё, исполнитель — только свои задачи и их объекты
- [ ] смена статуса только через проверку на стороне базы (функция/триггер — согласовать), таблица допустимых переходов
- [ ] история пишется только базой; INSERT/UPDATE/DELETE через API запрещены
- [ ] исполнитель не может менять поля задачи, кроме статуса через разрешённый переход
- [ ] открытая регистрация выключена
- [ ] сид: 1 постановщик, 2 исполнителя, 2–3 объекта, задачи в разных статусах
- [ ] проверка безопасности: скрипт/тесты, которые бьют в API от имени исполнителя и ждут отказа
