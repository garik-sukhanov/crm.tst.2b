# Решения и допущения

Что решили сами там, где ТЗ не даёт однозначного ответа. Пополняется по ходу работы; в конце из этого файла собирается пункт 4 сдачи.

## Стек

- **SPA на Vite, без серверной части.** Все правила доступа живут в базе (RLS и функции Postgres), поэтому отдельный сервер не нужен — фронтенд ходит в Supabase напрямую с публичным ключом.
- **Effector + Farfetched.** Бизнес-логика вынесена из компонентов в модели, что естественно ложится на слои FSD.
- **shadcn/ui + Tailwind.** Компоненты лежат в коде проекта, их можно править под себя; темы через CSS-переменные.

## Инструменты

- **Steiger** проверяет правила FSD (слои импортируют только нижележащие, срезы — через публичный API `index.ts`). Biome архитектуру не проверяет.
- **Стиль кода:** 2 пробела, одинарные кавычки, точки с запятой, ширина строки 100 — всё задаётся в `biome.json`, форматирование при сохранении (`.vscode/settings.json`).
- **`pnpm verify`** — единая проверка перед коммитом: Biome + Steiger + TypeScript.
- **TypeScript 7 (нативный компилятор).** У Steiger в зависимостях требование TS 5, но на работу это не влияет: проверка проходит.
- **Публичный ключ Supabase** лежит в `.env.local`, который не попадает в git. Шаблон — `.env.example`.

## Интерфейс

- **Объект — это канбан-доска.** Колонки — пять статусов, задачи — карточки. Так видно, что где застряло, без лишних экранов. Список задач в карточке объекта из ТЗ — это та же доска.
- **Перетаскивание только на десктопе и планшете.** На телефоне пять колонок не помещаются, а тащить карточку сквозь горизонтальный скролл неудобно. Там статусы — табы со счётчиками, а статус меняется кнопками на карточке. Кнопки есть и на десктопе: ТЗ требует показывать доступные действия.
- **Перетаскивание не даёт обойти правила.** Недоступные колонки гаснут, а итоговое решение всё равно принимает база.
- **Чат в задаче.** Кроме истории из ТЗ, в задаче можно переписываться. Писать могут те, кто видит задачу. Сообщения нельзя править и удалять — как и историю, это след договорённостей.
- **Одна лента.** Смены статусов и сообщения показаны вместе по времени, в базе это две разные таблицы.
- **Нижняя панель навигации на телефоне.** До «Объектов» и «Моих задач» дотягивается большой палец.
- **Темы.** Светлая, тёмная и «как в системе». По умолчанию — как в системе. Выбор запоминается в браузере.
- **Дизайн.** Нейтральные графитовые фоны, один сигнальный янтарный акцент. Цвет на экране несут только статусы задач. Шрифт IBM Plex с хорошей кириллицей. Моноширинная «бирка» с номером задачи (Т-014) — как бирка на стройке.
